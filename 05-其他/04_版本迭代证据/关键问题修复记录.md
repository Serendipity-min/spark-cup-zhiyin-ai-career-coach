# 职引 · AI职业诊断官 —— 关键问题专项修复与审计记录

在复赛备赛与 API 测试工程深度调优过程中，团队严格秉承“零修改线上工作流，全流程工程化闭环”的准则，针对状态机重入、异常中断、追问断言等关键问题进行了彻底修复与留痕：

---

## 修复项 1：P0-1 STATE_RESET 严格会话绑定与重置断言

- **问题描述**：早期测试脚本在执行状态重置测试时，Phase 2 容易生成随机新的 `uid` 或 `chat_id`，无法真正证明同一用户会话内历史状态被彻底清空。
- **整改落地**：
  1. 重构测试执行器，增加 `uid_override` 与 `chat_id_override` 显式传参支持；
  2. 生成固定的 `fixed_uid`（脱敏记为 `269689277c0c`）与 `fixed_chat_id`（`chat_sr_1789091667`）；
  3. **Phase 1**：跑通完整流程并产出诊断报告；
  4. **Phase 2**：在**同一会话（同一个 fixed_uid 和 fixed_chat_id）**下发送 `AGENT_USER_INPUT="你好"`；
  5. **硬断言校验**：首个中断返回必须为 Q1（识别目标岗位）。若直接进入 Q2/Q3 或保留前次岗位，直接判定为 FAIL。
- **验证结果**：✅ **VALID PASS**，原始日志落盘于 `STATE_RESET.jsonl`，证实状态清空率 100%。

## 修复项 2：P0-2 ABORT_AND_SWITCH 中断响应校验与同会话新岗切换

- **问题描述**：用户在诊断中途（如 Q2 阶段）希望放弃当前岗位并换投新岗位时，平台的中断指令响应与同会话重入能力需要严格证明。
- **整改落地**：
  1. **Phase 1**：在固定会话 `chat_as_1789091794` 启动“算法工程师”至 Q2 中断；
  2. **Phase 2**：向 `/workflow/v1/resume` 发送 `event_type="abort"` 指令；
     - 实测平台返回 HTTP 200，`code=23802`，`message="Question-answer node data retrieval timeout(Received abort instruction)"`；
     - 显式校验包含 `Received abort instruction`，非预期 code 直接判 FAIL；
  3. **Phase 3**：在同一 `chat_id` 下发起新岗位“产品经理”；
     - 工作流正确识别并反馈：“收到，你的首选方向是 产品经理”，并顺利进入后续轮次；
     - 最终报告经严格文本扫描，**100% 为产品经理内容，算法工程师残留率为 0.0%**。
- **验证结果**：✅ **VALID PASS**，原始交互轨迹落盘于 `ABORT_AND_SWITCH.jsonl`。

## 修复项 3：P1 关键场景中断轮次硬断言完善

- **问题描述**：早期测试仅判断最终是否生成报告，未严格核验特定业务分支的中断轮次是否精确符合设计。
- **整改落地**：在 `career_cases.yaml` 与 `assertions.py` 中引入 `expected_interrupt_rounds` 硬断言：
  - `T02`（首句给岗位）：强制断言中断轮次精确为 **2 轮**（跳过 Q1 直接进入 Q2）；
  - `T08`（学历残缺）：强制断言中断轮次精确为 **4 轮**（第 3 轮精确追问年级）；
  - `T01, T09, T10`（标准黄金路径）：强制断言精确为 **3 轮**。
- **验证结果**：✅ 全量用例中断轮次与设计预期 100% 一致。

---

## 修复项 4：外部检索超时降级与空结果兜底

- **优化说明**：
  1. 当目标岗位过于冷门或企业公开校招平台反爬导致无匹配 JD 时，工作流自动启用超时降级策略与常识库兜底，标注“建议结合目标企业最新 JD 核对”，绝不因外部依赖导致工作流崩溃；
  2. 知识库检索若未命中高相关度片段，大模型遵循“知之为知之”原则，不在报告中伪造“依据知识库可知”，确保输出严谨可信。
